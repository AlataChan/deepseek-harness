## Constraints

- **Overlay-only, fork-owned packages included.** No edits to upstream-owned packages (`packages/api/*`, `packages/core/*`, `packages/client/ui-*`, `packages/subagent/*`, `apps/desktop`, `packages/bundle/desktop-app`, `desktop-companion`). New code lives in `packages/experimental/*`; retirement, dispatch-admission, and scope-enforcement changes land in fork-owned experimental packages (`agent-team`, `tool-agent-team`). `apps/cli` dependency rows, `scripts/desktop-profile-plugins.json` pins, and `scripts/upstream-intake-registry.ts` rows are the existing fork-owned delivery surfaces.
- **Explicit overrides are separated from observed usage.** A conversation override is an explicit record owned by the new catalog: written by the assistant's own model control, and seeded from durable `model/selection` events on bound sessions (live via `session/event`; on binding creation and cold resume by reading the persisted log through the fork read-handle pattern, `agent-team/src/persisted.ts:22-33`, where the latest eligible `model/selection` event wins). The catalog stores an explicit selected-or-inherit state and a durable replay checkpoint: clearing commits inherit plus the checkpoint atomically, rather than deleting the record. Binding creation seeds once; cold resume considers only selection events newer than the checkpoint, so earlier selections cannot resurrect a cleared override. Observed usage — `request/header` and the projection's `lastUsed` — is never treated as user intent, and a route the overlay itself applied is never promoted into an override.
- **Conversation-only model selection is preserved.** The resolved route = explicit conversation override → team-seat override → profile default. Every selectable surface this feature ships writes only its own scope: the conversation control writes the conversation record, the assistant drawer writes the profile, the team editor writes the seat. The app default model is never written by any feature path, and the acceptance proves it for each surface. The official session picker's pre-existing global save is app behavior outside this feature; S8 evaluates shadowing the session model seat for assistant-bound sessions so the conversation-scoped control is the path users get there.
- **Model routing is validated before admission and applied only at request boundaries.** A route change is validated against the served catalog (`ctx.llm.resolveCallConfig` + availability) before it is accepted; it never takes effect mid-stream; and when a request carries images admitted under a different route, the mismatch fails visibly with a retry path (`llm-deepseek/src/images.ts:46-48` throws `UNSUPPORTED_CONTENT`) — images are never silently dropped or sent to a route that cannot accept them.
- **Home surfaces stay inside fork-owned occupants.** `conversation.hero.*` seats are single-occupant and only their declaring entry may render them (`packages/client/ui-slots/src/index.ts:365-368`), so new home cards render through a list child seat declared by the fork-owned occupant of `conversation.hero.agentTeam` (`client-ui-agent-team/src/client/mount.ts:116-123`), following the `conversation.hero.capabilities.item` precedent (`desktop-ask-data/src/client/CapabilitiesMenu.tsx:25-34`).
- **Model-visible ⟺ logged.** Role, memory, and route inputs reach models only through logged `system/message` and `request/header` records. New fork session events are `ignorable: true`, acknowledged in `docs/persistence-changes/`, and registered in `scripts/upstream-intake-registry.ts`.
- **Enforcement lives in the operation that decides.** Retirement, scope, routing, and permission checks are enforced in the Host admission paths every caller uses, never only in UI or prompt text.
- **No new heavy dependencies**; packaging must keep the one-click DMG working (`scripts/verify-desktop-bundle.sh`, invoked by `build-dmg.sh`).

## Acceptance Criteria

- A user can create an assistant (UI or model tool), talk to it privately, start a new topic, change its model or responsibility, restart the app, and reopen it — with saved settings applied and the application default model unchanged by every selectable surface, asserted per surface.
- A conversation-scoped model selection stays conversation-only: it survives consumption and restart, is never promoted into a profile or the app default, and a profile/seat change propagates only to conversations without an explicit override. Clearing durably restores inheritance; restart and replay never revive a selection older than the clear checkpoint.
- One profile participates in two teams and a private conversation without leaking private or other-team context; cross-scope access is refused through remotes, model tools, search, references, and data/knowledge providers.
- Existing institution teams are adopted without respawn and without diverging from concurrent legacy catalog writes; a failed spawn is replaced without name reuse and without consuming extra capacity; retired seats reject routing; crashes at every provisioning checkpoint recover without duplicate members, sessions, or operations.
- Explicit memory is injected as a versioned logged snapshot; removal excludes it from future injection/recall/search while the UI states that session history is retained.
- Stage C: ordinary group messages dispatch one coordinator; references never dispatch members accidentally; keyed admission and posting deduplicate under crash recovery; cancellation never interrupts unrelated execution; submissions that bypass the team paths are detected and surfaced, never silently interleaved; predictions never submit and cannot apply after typing or navigation.
- Route and capability mismatches fail visibly (unavailable route, images routed to a model without image input) with a retry path, never by substitution or silent drops.
- Every model-visible addition has a log record and a keyless recorded-session case; TypeScript and Python SDK outputs are updated when the session event map or lifecycle changes.
- The packaged DMG builds from freshly built Tauri artifacts and behaves correctly on fresh and copied existing profiles.

## Non-goals

- Stage D items: continuous multi-part chat rotation, assistant-bound scheduled work, per-assistant embedded browser, richer secrets UI, realtime voice.
- Cross-device synchronization; destructive profile/team deletion; per-seat cwd; different workspaces per seat; runtime reparenting.
- Any modification to upstream-owned packages, or any dependency added to a release package that names an experimental one.
- Windows EXE packaging (existing separate pipeline) and media/runtime bundling.
