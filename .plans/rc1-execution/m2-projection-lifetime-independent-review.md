# Independent projection lifetime review

Review date: 2026-11-05. Scope: all production `sessionProjections.register` call sites under `packages/**/src`, current working files, Cordis ownership implementation, and retained model-selection readers relevant to M2. Read-only product audit; this report is the sole intentional file write. No tests, package commands, builders, installs, generators, paid APIs, Git mutations, or subworkers were run. Root owns final acceptance. Findings below are source-derived, not runtime reproduction or claimed passing checks.

## Verdict

Do not apply a blanket “wrap every awaited registration in another effect” repair. The registry already installs the registration on the calling fiber before its asynchronous handoff. Seventeen remaining dispose-only post-await effects are redundant ownership, and their late installation is a real `INACTIVE_EFFECT` failure opportunity. Some callers also install useful effects after the await: removing only their redundant disposer removes one failure site but does not make their whole initialization unload-safe. Team and the attachment-dependent image-limits registration intentionally cross ownership scopes and require explicit release by the shorter-lived owner.

The four root repairs named in the task are present: `ApiSessionList.open`, `installModelSelectionProjection`, `DesktopAskKnowledge.openProjection`, and `PlanModeController[Service.init]` start their outer effects before awaiting registration. They no longer perform the former post-await `ctx.effect` installation at those points. I found no remaining unowned projection reference in the owner-local registrations themselves. Remaining risks concern late continuation effects and foreign-scope resources, not invalidation of retained readers.

## Implementation evidence and interleaving

- `vendor/cordis/src/service.ts:41-57` installs service tracker metadata with property `ctx`; `vendor/cordis/src/utils.ts:118-124,150-198` rebinds traced service access to its use-site context. Therefore `ctx.sessionProjections.register(...)` uses the caller's fiber, not automatically the registry provider's fiber.
- `packages/session/session-projection/src/index.ts:383-446`, `SessionProjectionRegistry.acquire`: `this.ctx.effect(...)` synchronously acquires/increments the registration and supplies its reference-decrement cleanup; `onEffect(dispose)` runs before `await Promise.resolve()`. Only afterward does `assertActive()` precede handle publication. Final release sets refs to zero; drive/snapshot participation stops. A second handle disposer cannot decrement twice because the Cordis effect disposer is single-shot.
- `vendor/cordis/src/fiber.ts:353-357,431-435`: effect creation checks cleared uid and `UNLOADING`. `acquire`'s later `assertActive` checks uid only, not `UNLOADING`, and cannot reserve the caller's next continuation. An unload after this check but before the caller resumes can let `await register` succeed and the next `ctx.effect` fail.
- `vendor/cordis/src/fiber.ts:365-404,476-566`: an effect installed before an await is visible to disposal immediately; disposal joins async setup and collects its eventual returned cleanup. Returning a disposer from an already-running async effect differs from calling a new `ctx.effect` after await.
- `vendor/cordis/src/fiber.ts:681-740`: ordinary class/function plugin load is awaited by `_reload`, which then unloads a superseded activation. Actual disposal clears uid before waiting for that load; stale load continuations can still attempt effect creation and log failures. During an ordinary dependency restart, loading and epoch transitions are serialized; do not claim every await automatically leaks.
- `packages/session/session-projection/src/index.ts:54-81,434-445,839-878`: `stateOf`/`readerFor` close over the original registration; reads fold forward through `cellFor`, even after release. Reads need neither a live registry key nor a newly installed effect. A new registration after final release gets a new registration object, so retained readers keep the old definition.

Concrete problematic schedule: register installs its owner-local effect; registry resumes and constructs a handle; owner disposal clears uid before the caller's continuation; caller resumes and calls `ctx.effect(() => () => handle.dispose())`; that call throws `INACTIVE_EFFECT`. The original effect still releases the reference during owner teardown. This is a late-effect startup failure, not evidence of a leaked reference.

## Required fixes and cautions for root

1. **Remove redundant late ownership in handle-only service initializers.** The deletion dispositions above are the minimal correction. Do not add another wrapper solely to call `handle.dispose`, and do not introduce a second cancellation state machine. Bare awaited assignment is sufficient for ownership, as demonstrated by AgentRegistry's initializer. Registry rejection during an owner unload remains a possible initialization rejection; avoiding a duplicate late effect is not a promise that every unload-related rejection disappears.

2. **Protect useful post-await activation, not just handle cleanup.** `AgentLoop[Service.init]` still calls `ctx.effect` for `agents.setFactory`, transaction disposal, and configured resume injections after `Promise.all`. Likewise todo/time/tmux/retry/subagent/commerce-tools install real contributions after awaiting their projection. Removing a duplicate disposer does not repair these subsequent sites. If root requires clean cancellation, check the actual fiber's activation eligibility immediately before the synchronous installation phase (including UNLOADING as well as uid disposal), or move that phase into a correctly owned injected child whose creation is gated by the live owner. An early async effect can own returned cleanup, but its body is not permission to call new effects on a disposed context. Preserve required useful cleanup; do not delete factory, listener, abort/drain, or tool cleanup as “redundant.” A narrowly defined cancellation exit is preferable to blanket catching errors from the whole installer.

3. **Team tool mounts are foreign-fiber resources.** In `tool-agent-team.apply`, `install(agent, agent.ctx, ctx, resolved)` attaches tools to an Agent's live fiber; their aggregate disposer is installed on the plugin only afterward. Today the redundant effect at 546 rejects a stale plugin before reaching this work, so the after-await unload schedule alone does not demonstrate an existing leaked mount. Simply deleting line 546 permits the stale continuation to install Agent-owned tools at 552 before `ctx.on` at 553 fails, leaving no plugin-owned aggregate cleanup at 558. Minimal safe repair must gate installation against the plugin lifetime and establish aggregate cleanup before the first Agent mount, with rollback if synchronous reentrant unload interrupts installation. Retain each returned foreign-scope disposer; the projection registry cannot clean these tools. `tool-subagent.apply` also has descendant `candidate.ctx.inject` mounts at 676; preserve their existing ancestry ownership when changing initialization and do not treat them as projection references.

4. **Keep Team root-release ordering.** Removing Team's returned `handle.dispose` because register is effect-owned would keep its root-owned ref until root teardown and leave Team in live snapshot/drive participation after Team unload. The existing early effect joins pending setup; its `finally` releases even if `disposeRuntime` fails, and retained TeamJournal reads can still use that handle while runtime drains. No additional Team wrapper is justified by this audit.

5. **Keep image-limits child ownership.** `ApiSessionList.open` calls outer `ctx.sessionProjections.register` inside an attachment child's early effect. The child release is necessary on attachments disappearance while the controller remains active; underlying owner-local release occurs only when outer ctx unloads. A deliberate alternative is registration through `attachmentCtx`, but deleting the existing explicit child disposer without that change is wrong. Metadata's map-removal cleanup is also useful independently of reference release.

6. **Permission seeding is not a disposer.** `PermissionPresetService[Service.init]` assigns the handle and calls `pinInitialPermission` for existing sessions before its redundant effect. If root changes cancellation policy here, gate that mutation phase rather than pretending removal of line 282 prevents post-unload seeding. This audit does not classify the pure handle assignment as a resource leak.

## Retained model-selection and M2 compatibility

`packages/core/agent-loop/src/index.ts:534-535` binds model and inbox readers with `readerFor(session)` and passes them to `ReactLoopAgent`; `packages/core/agent-loop/src/agent.ts:150` constructs `AgentModel` with the model reader. `packages/core/agent/src/model-selection.ts:126-169` reads that retained callback. This path does not do a live registry-key lookup on `current()` and therefore remains readable after factory projection release or same-key replacement. Do not change it to `ctx.sessionProjections.stateOf(session, 'modelSelection')`, which rejects/returns absence after release and can select a replacement unit. Reader retention does not authorize sending work on a disposed Agent; it preserves read semantics only.

Preserve the observable source semantics together:

- `Model.current(): Readonly<ModelSelection> | undefined` remains a method (`runtime-types.ts:44-51`). `AgentModel.current` returns a detached selection in precedence order pending selection, last-used request route, then complete live options; incomplete provider/model options yield undefined. Read does not append or resolve adapter defaults.
- Origin is separate: `Model.origin()` / `AgentModel.origin()` returns explicit, inherited, or null. Header-only and live-option fallbacks have null origin; a consumed matching inherited selection retains inherited origin. Do not infer an explicit choice merely from a nonempty `current()` result.
- `modelSelectionProjectionDefinition` is stateVersion 4 (`model-selection.ts:83-118`) with lastUsed, pending, lastUsedOrigin, pendingOrigin; its wire view is still `{ lastUsed, next }`, with next = pending ?? lastUsed. Host `current()` may use live options while wire `next` is null; this is intentional source distinction, not a projection omission to fill with defaults.
- Header folding omits adapter-defaulted reasoning effort, consumes only an exactly matching pending selection, and preserves pending choices across nonmatching headers. `select` considers origin as well as route/effort when deciding whether to append. API installation imports this same v4 definition; do not reintroduce an older competing v2 definition.
- `packages/api/session-controller/src/agent.ts:282-307`, `ApiSessionAgentController.selectionFor`, retains its separate `picked` override, adopts prepared selection without recording a fresh model selection, and falls back to `agent.model.current()` then defaultModel. Do not flatten that preparation state into wire `next` or treat it as a registry ownership defect.
- Source adaptation is real: the exported AgentModel constructor now takes a reader, Session, options; all production construction found in this audit goes through `agent-loop/src/agent.ts:150`. Update direct test/consumer construction to supply the reader rather than passing a Context or fabricating projection state from the registry. The retained-reader constructor change does not justify changing `current()` into a property or extending its return with origin fields.

Existing test sources inspected, **not executed**: `packages/session/session-projection/tests/registration-reader.spec.ts` covers lazy binding, retention after owner disposal/version replacement, post-disposal reads, and owner disposal before handoff; `tests/compatibility.spec.ts` covers legacy callable registration ownership and composed effects. `packages/core/agent/tests/model-selection.spec.ts` covers detached current values, live options fallback, defaulted effort, explicit/inherited origin, and header-only origin. These are test intentions, not acceptance evidence. Focused missing evidence for root to obtain: disposal between handle readiness and caller continuation, useful post-await installer cancellation, Team root-ref removal while root stays live, attachment-child ref release while controller stays live, and actual Agent.model.current/origin reads after original registration release plus replacement. No passing claim is made here.
