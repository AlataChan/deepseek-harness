# 桌面发布准备与发布

[English](desktop-releases.md) | 中文

桌面构建默认为 `internal`：未签名的 Windows 安装程序以及临时签名、未经公证的 macOS 镜像仅用于受控测试。将 `DSH_DESKTOP_ARTIFACT_DIR` 指向空的候选目录，避免替换已交付的安装程序。每次构建都会在外部生成 `.release.json`，记录已测试的源码、运行时与外壳版本、目标平台、适用的 CI 运行及尝试编号、安装载荷摘要，以及最终产物大小和 SHA-256。本机构建不能冒充通过公共发布资格核验的 CI 产物。

## 准备候选产物

1. 构建工作区和冻结的知识库辅助进程，然后在 Windows 上运行 `node scripts/build-exe.mjs`，或在 macOS 上运行 `bash scripts/build-dmg.sh --arch arm64`。Windows 自定义模板基于 Tauri CLI 2.11.4；模板头部记录了上游模板摘要。更新模板必须保留 WebView 安装、注册表、快捷方式、文件关联和卸载程序行为。
2. 对临时安装或只读挂载的 DMG 执行安装后验证。Windows 工作流要求安装程序退出码为零、安装后就绪检查、知识库 Host 检查，以及原生 `scripts/tests/desktop-installer-upgrade.ps1` 检查。该脚本使用生产事务包含文件编译真实 NSIS 样例，覆盖 A 到 B 升级、临时与永久辅助进程锁、发布失败、回滚失败、中断恢复、重新安装，以及辅助进程重启。源码测试不能证明原生升级验收通过。
3. 公共模式需设置 `DSH_DESKTOP_BUILD_MODE=public`。Windows 需要 `DSH_WINDOWS_CERTIFICATE_THUMBPRINT` 对应的私钥存在于当前用户证书存储中，并且 `DSH_WINDOWS_PUBLISHER` 与受信证书主题一致。macOS 需要 `DSH_MAC_SIGNING_IDENTITY`、`DSH_MAC_TEAM_ID`，以及钥匙串中已认证的 `DSH_NOTARY_PROFILE`。缺少凭据会在构建前立即失败。最终资格核验调用原生 Authenticode 或 Developer ID、操作系统信任、公证和装订检查；清单中的声明不能替代这些检查。

## 恢复中断的 Windows 升级

安装程序先在安装目录旁暂存完整候选载荷，再替换现有安装。它对已安装的主程序、Node 辅助进程和知识库辅助进程执行独占访问探测，仅对访问、共享或锁冲突重试，每个替换步骤最多十秒。它不会终止 Node 进程。替换失败会保留旧载荷，并报告暂存、备份和事务日志路径。如果事务日志存在而当前安装缺失，可恢复备份；安装程序随后以失败退出，要求重新运行。状态不明确时保留两个目录供操作人员检查。

升级成功后，旧安装保留在旁边的 `*.octopus-backup-*` 目录。这会额外占用磁盘空间，但能保留不归安装程序所有的文件。确认新安装正常，并检查备份中是否有个人文件后，操作人员可以移除该特定备份。自动清理不会触碰用户主目录、知识库、原始文件、会话或凭据。替换或回滚尚未解决时，不要移除恢复目录。

## 明确规划并发布

发布仅面向 `AlataChan/deepseek-harness`。规划前，需在已测试的确切提交上创建版本发布及标签 `desktop-v<version>`，并创建独立频道发布及标签 `desktop-channel-<channel>-<target>`。发布程序不会创建或移动标签。每个平台拥有独立的权威频道记录，因此发布 Windows 不会丢失 macOS 下载位置。这些记录用于下载，不会启用自动更新程序。

使用手动 `Desktop release publication` 工作流，首先选择 `operation=plan`，指定成功打包的确切运行编号、尝试编号、提交、产物名称及目标平台。它下载安装程序和清单，独立查询 GitHub 运行、作业和安装后检查证据，仅安装到临时目录或只读挂载，并调用原生签名核验。调用 `verify` 或 `publish` 前审查输出的计划 JSON；这两个操作要求提供审查过的原始 JSON。`plan` 和 `verify` 不写入发布。即使旧清单声称通过，未签名的公共输入也会被拒绝。

发布程序先上传不可变的带版本号二进制文件，再下载并比较大小和摘要，最后更新频道记录。相同对象会复用，冲突对象会拒绝。二进制上传或回读失败时，已上传的有效文件保留，可用同一计划继续。频道操作失败后，重跑前必须先核验；如果删除成功但替换失败，应针对观察到的缺失记录明确重新规划。发布工作流通过仓库级并发组串行执行受支持的写入。GitHub 发布资产替换不是原子比较交换：程序会在替换前后检查观察到的修订，但不支持绕过工作流手动写入频道，发生此类操作需人工协调恢复。

签名凭据、原生签名成功证据，以及原生 Windows 升级验收属于外部前置条件。缺少证据仍记为待验证；源码或样例测试不能赋予安装程序公共分发资格。
