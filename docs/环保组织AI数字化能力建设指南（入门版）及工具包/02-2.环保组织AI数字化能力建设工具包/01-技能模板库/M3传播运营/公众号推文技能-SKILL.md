# 公众号推文技能（传播运营 · M3）

基于机构素材生成公众号推文初稿。核心要求：像机构自己人写的，不像AI写的。

## 什么时候用

- 用户提供了活动记录、项目数据、案例故事、照片说明等素材。
- 用户要发**公众号推文**（机构动态、项目进展、活动招募、案例故事）。
- 触发关键词：公众号、推文、文章、发一篇、传播稿。

不要用于：内部复盘（用活动复盘技能）、正式结项报告（用结项报告技能）。

## 工作流程

1. 读取机构历史推文（知识库中 L1 公开档）2–3 篇，学习机构的语气、句式、排版习惯。
2. 从本次素材中挑最有画面感的一个细节做开头。
3. 按下方结构写初稿。
4. 全文自查：删掉所有正确的废话。

## 需要的输入

- 本次推文的素材（活动记录、数据、故事）。
- 机构历史推文 2–3 篇（文风参照，强烈建议提供）。
- 品牌话术表（若机构有：标准介绍、口号、禁用词）。

## 输出契约

输出 Markdown，结构如下：

1. **标题**（给出 3 个备选：一个平实、一个具体、一个带细节）
2. **封面摘要**（≤50 字，公众号摘要栏用）
3. **正文**（600–1200 字：场景开头 → 经过 → 数据 → 人话结尾）
4. **配图建议**（每张图配一句话说明）
5. **待核实项**（不确定的事实和数字）

## 避坑要点（质量约束）

- 禁用套话：「随着……的发展」「具有重要意义」「圆满成功」「在这个……的时代」。发现一处删一处。
- 禁用悲情绑架：「再不行动就晚了」「最后的希望」。
- 数字必须有出处，没有就写定性描述并列入待核实项。
- 涉及受益人必须脱敏（化名、删联系方式）。
- 第一段不许用「为了……，我们开展了……」这种公文开头。用一个具体场景或细节开头。
- 文风向机构历史推文看齐，而不是向「标准公文」看齐。

## 模板（替换括号内容）

```markdown
# 标题备选
1. 【平实版】
2. 【具体版】
3. 【细节版】

# 封面摘要
【≤50字】

# 正文
【用一个具体场景开头：那天的天气、一个人的动作、一个意外的小细节】

【经过：做了什么，按时间或按亮点】

【数据：只写有出处的数字，自然融入，不堆砌】

【结尾：一句人话。不落款喊口号】

# 配图建议
- 图1：【画面描述】配【一句话】

# 待核实项
- 【不确定的事实/数字】
```
