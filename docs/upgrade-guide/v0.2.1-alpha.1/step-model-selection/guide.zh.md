# 在准备步骤之前选择模型

[English](guide.md) | 中文

## 变更

插件过去可以在 `agent/request` 中修改提供商、模型或推理强度。现在，这些字段在工具解析、提示组装和 `agent/pre-step` 之前就会被捕获。请求监听器如果修改已捕获的选择，会被拒绝。监听器仍可约束 `maxTokens`，包括执行轮次的预算限制。

`Agent.model.current()` 依次读取持久化的待用选择、最近记录的请求以及 `AgentOptions`。未指定推理强度时，不会固定提供商的默认值。因此，恢复会话时，仅传入不同的 `AgentOptions` 不会替换已记录的选择。

`Agent.model.origin()` 区分显式选择、继承的配置选择以及仅来自请求头或选项的回退值（`null`）。同步助手配置时调用 `select(selection, 'inherited')`；用户选择时省略该参数。同一路由的来源发生变化时，也会记录这一意图，包括清除模型覆盖。历史选择事件未记录来源时，仍按显式选择处理；仅有历史请求头不代表用户作过显式选择。来源元数据不会进入提供商的请求配置。

这会影响在请求组装期间选择路由的插件和自定义入口集成。桌面模型选择仍经过原有 Host 控制器。会话日志仍可读取；不兼容的模型选择投影缓存会从日志重新折叠，不会直接当作当前值使用。

## 迁移

1. 查找 `agent/request` 监听器中的路由修改。将提供商、模型和推理强度的修改替换为在目标步骤开始准备之前调用 `agent.model.select(selection)`。保留其他请求约束，并在瀑布流监听器中调用 `next()`。
2. 渲染依赖模型的指令或检查能力时，读取提示组装或步骤前上下文中已捕获的 `modelSelection`。捕获之后作出的选择只影响后续步骤，不会改变正在进行的请求或其重试。
3. 替换 `ModelSelectionRef` 和双参数 `installModelSelection` 辅助函数。该函数现在只接收 Agent 上下文；持久化选择由 `Agent.model` 持有。自定义 Agent 实现和类型化测试夹具需实现其 `current()`、`origin()` 和 `select()` 方法。
4. 如需覆盖恢复会话的选择，在下一步开始前显式调用 `agent.model.select()`。希望提供商选择默认推理强度时，不要传入 `reasoningEffort` 属性。
5. 在模型切换、重试和冷恢复时覆盖显式选择恰好等于配置默认值、以及随后清除覆盖的情况。核对实际请求的提供商、模型和推理强度。确认提示变量和能力检查使用同一选择，且执行轮次的 `maxTokens` 预算限制仍然有效。
