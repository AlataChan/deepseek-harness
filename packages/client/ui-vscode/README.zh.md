# @deepseek-ai/dsh-client-ui-vscode

[English](README.md) | 中文

仅用于 VS Code 的客户端 UI 插件，负责显式编辑器上下文和扩展所选工作区的导航。它在会话 composer 中添加一个紧凑菜单，注册 `ide-context` 引用 codec，并且只消费嵌入式 Webview shell 提供的类型化 `vscodeIde` 方法与事件。

选区、当前文件和当前文件诊断操作会在扩展 host 中捕获不可变快照。Webview 按不透明 id 保留每个已接受快照，并把普通引用 chip 插入当前草稿。提交时，每个 chip 会序列化为经过转义的 `<ide_context>` 文本，结果提示词仍经现有 Session 路径发送。快照缺失或序列化失败会阻止提交，绝不会回退到较短的剪贴板标签。

扩展所选根目录经 `workspaces.create` 注册，经 `workspaces.connectWorkspace` 连接，再经 `sessions.open` 打开。根目录变更串行处理，因此一次失败的选择不会阻断后续重启。

## 模型体验

### 显式编辑器快照

#### 模型看到的内容

显式附加的快照成为普通且已记录的用户消息文本。模型会在一个 `<ide_context>` 块中收到捕获内容及其 URI、可选的工作区相对路径、语言、文档版本和范围。当前编辑器、选区、未保存文本或诊断都不会被隐式提供。

#### Token 影响

每个已接受的 chip 会向提交的用户消息增加一行经过转义的元数据、精确且有界的快照文本以及一行结束标记。仅打开菜单或捕获但不提交上下文不会增加模型 token。

#### KV Cache 影响

编辑器上下文只改变包含它的那次提交的用户消息后缀。插件不添加系统提示词段。

## 已知局限与延后工作

- 捕获只存在于保留的 Webview 中；view 被销毁、窗口重新加载或扩展 host 重启后会丢失。
- 诊断捕获仅覆盖当前文件，而非工作区中的每个文件。
- v1 的 `@` source 仅供显式操作使用，不向候选菜单贡献条目。
