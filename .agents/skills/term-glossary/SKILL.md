# 术语词表（本地）

完成用户当前任务的前提下，把用户没说出来的准确术语顺带点出来：术语名 + 一句白话解释。词表是本地文件，查询脚本不联网。

## 每轮检查

发送进度或完成结果前，检查用户本轮新增的话：

- 用户用口语描述了某个控件、效果或状态（"鼠标放上去""点了弹出来""存东西的地方"）：照常把活干完，在结果里顺手点 1 个最相关的术语。
- 用户问"这叫什么"、"怎么说才专业"：先给可以直接用的结果，再补术语。
- 用户要改写需求：给一段保留原意、可以直接发给 Agent 的话，再加术语提示。
- 用户已经用词准确：正常干活，不重复教学。

不要因为前几轮已经开始编程就跳过本轮的检查。

## 怎么查

先自己推断 1-3 个候选术语（"悬停"、"Tooltip"），或把用户的口语提炼成短词，一条命令批量查（脚本本地运行，不联网）：

```bash
node "${DSH_HOME:-$HOME/.dsh}/skills/term-glossary/scripts/lookup.mjs" --query '悬停' --query '鼠标放上去'
```

（脚本位于本 skill 的 `scripts/lookup.mjs`；对话里通常给出本 skill 的目录，按实际位置替换上面路径。）

- 查询词一律用单引号包裹，且只放你提炼后的短词；用户原话里出现引号、`$`、反引号时不要原样拼进命令。
- 只采纳真正符合当前场景的命中；只是字面沾边、语境对不上的不要用。
- 结果里的 `plain` 是我们自己的白话解释，可以按语境改写，但不要编造词表之外的术语或解释。
- 没有命中就继续干活，不用提术语；用户明确问起时如实说词表里没有。
- 如果 shell 里没有 `node`：改用桌面自带的 Node 运行同一个脚本，例如 `"/Applications/octopus_DSH.app/Contents/Resources/resources/node"`（应用装在别处时，找 app 里的 `Contents/Resources/resources/node`）；都不可用就跳过术语提示，不要把报错抛给用户。

## 表达方式

把术语自然写进已经交付的结果里，第一次出现带一句解释：

```text
已给下载按钮加上悬停（Hover）变色：鼠标放上去时颜色加深。
```

- 每轮最多提示 3 个术语，优先最能消除歧义的那一个。
- 默认不回显链接（链接只是出处）；用户问来源时再给。
- 不开小课堂、不列术语清单、不展示词汇量。
- 能用大白话讲清楚就用大白话；术语是为了让下一次表达更准，不是表演。
