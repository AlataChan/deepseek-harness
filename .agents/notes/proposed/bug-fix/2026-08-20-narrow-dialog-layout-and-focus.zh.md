# Agent Note: 窄幅弹窗布局与焦点归属

Status: proposed

[English](2026-08-20-narrow-dialog-layout-and-focus.md) | 中文

## Problem

交互式客户端在狭窄的 VS Code 活动栏 Webview 中渲染时，设置弹窗仍保留 188 像素的导航栏。内容列因此被压缩到控件和说明文案所需宽度以下，出现逐字换行、重叠、裁切和横向滚动。

共享 `Modal` 原语和设置弹窗虽然声明了 `aria-modal="true"`，却没有持有键盘焦点。打开弹窗后，焦点可能仍留在遮罩后的控件上；Tab 可以进入背景控件；关闭后也不能可靠地把焦点交还给触发控件。嵌套弹窗同样需要唯一且明确的键盘归属方。

## Proposal

视口宽度不超过 640 像素时，设置弹窗使用单列纵向布局：导航变成位于内容上方、可横向滚动的紧凑行，内容则占用完整弹窗宽度。更宽的视口继续使用现有双列布局。

一个共享的弹窗焦点 hook 会记住触发控件、选择初始焦点目标、把 Tab 与 Shift-Tab 限制在最上层 `aria-modal` 弹窗中、只把 Escape 路由给该弹窗，并在弹窗卸载时恢复触发控件焦点。共享 `Modal` 原语和设置外壳都使用这一归属机制，使嵌套弹窗遵守同一规则。

## Alternatives considered

**要求用户加宽活动栏。** 插件无法假定或控制该布局，默认宽度下的视图必须在不调整 VS Code 的情况下保持可用。

**缩窄导航栏但保留双列。** 在 300–400 像素宽的 Webview 中，标签仍会占据大部分宽度，留给功能设置的空间仍然不足，因此只能推迟问题而不能消除问题。

**在每个弹窗中分别修补焦点。** 独立的 document listener 会发生行为漂移，并在嵌套弹窗中冲突。单一可复用归属方让每个弹窗获得一致的初始焦点、焦点约束、Escape 和恢复行为。

## Acceptance criteria

各设置分区在默认宽度的 VS Code 活动栏中保持可读、可操作，并在浏览器宽度的视口中维持既有宽屏布局。单元测试固定窄屏样式规则、进入焦点、两个方向的 Tab 回绕、最上层嵌套归属、Escape 与触发控件焦点恢复。重新构建的 VSIX 通过相同的真实 VS Code 工作区、设置和目录弹窗冒烟路径。

## Risks

最上层归属依据已挂载 `aria-modal` 弹窗的文档顺序，这与 portal 到 body 的子弹窗和设置外壳一致。如果消费方把视觉层级更高的弹窗渲染在文档顺序更早的位置，应调整其 portal 顺序，而不是增加另一套键盘 listener。
