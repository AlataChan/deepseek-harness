# Agent Note: 外部工具结果围栏采用定向结构转义

Status: implemented

[English](2026-09-14-external-tool-result-fence-policy.md) | 中文

## 问题

第三方工具结果可能包含模仿系统分隔符、消息角色或编码分隔符的文本。若在没有解释标记的情况下把这些文本交给模型，外部内容就可能与 Harness 指令竞争。转义所有标点会破坏代码、URL、shell 示例和普通语言，而无界转换也可能绕过现有工具结果溢出策略。

## 决策

`dsh-fence-policy` 对配置工具的根调用结果文本执行一次不做规范化的线性扫描。它移除固定的不可见格式码位集合，替换不允许的控制符，并且只在结构位置转义分隔符起始字符、字符引用的 `&` 和行首角色冒号。固定的兼容码位表让安全相关的易混淆字符集合可以接受审查，并可针对运行时 NFKC 数据测试。

每个转换后的文本块都带有闭合的 `<external-data>` 围栏。一个稳定的 `guard:external-data` 系统提示词区段要求模型把围栏文本视为数据而不是指令，其位置为集中分配的 `SECTION_ORDERS.EXTERNAL_DATA` 位置 700。Web 工具返回的渲染文本不包含逐结果的不可信内容提示，因此该区段是唯一的解释提示。

`dsh` 基础 bundle 在溢出策略之后直接挂载围栏策略，配置为 `tools: [web_fetch, web_search, 'mcp__*', ask_knowledge_retrieve, ask_knowledge_lookup, run_code]` 和 `maxMixedTextBytes: 50000`；后者等于溢出策略的 `maxInlineBytes`。执行后监听器先委托，并保留阻止决策、显式值替换、带父调用的调用、非文本块及下游上下文。`run_code` 在根调用处加围栏，因为 PTC 子分派值只通过该根结果到达模型。未标记作用域的事件传递覆盖同一组合内进程内子智能体发起的直接根调用；模型把内容转发到参数以及进程外组合不在本策略范围内。

大小责任按结果类型划分。`dsh-spill-policy` 的前置监听器会接收围栏策略的下游转换，因此由它限制完整的围栏纯文本结果。溢出策略跳过混合结果，所以围栏策略单独限制其中围栏文本的 UTF-8 聚合字节，同时保留非文本块。上限若无法容纳一个围栏和截断后缀，则移除所有文本块。

## 考虑过的替代方案

**匹配前规范化全部输入。** 未采用，因为规范化会改变普通第三方内容，无法说明字节保真性；固定兼容查找可以在不改写返回数据的情况下检测相关易混淆字符。

**转义所有尖括号和 `&`。** 未采用，因为这会破坏不构成结构标记的比较表达式、重定向、URL 查询字符串和代码。

**由围栏策略为所有结果设置一个上限。** 未采用，因为这会重复纯文本溢出策略，并可能在溢出存储记录完整围栏结果之前截断内容。

**使用模式黑名单清理器。** 未采用，因为枚举标签拼写、标点变体和嵌套结束标记并不完备；结构转义无需枚举即可中和分隔符形式。

**在每个工具结果中放置不可信内容提示。** 未采用，因为同一解释规则会分散在多个工具中，而 MCP 和 Ask Knowledge 结果没有等效提示。

**向 `ToolDefinition` 添加信任标志。** 未采用，因为执行后监听器已经可以表达该策略，为此更改核心工具契约没有必要。

**改写带父调用的 PTC 值或阻止内容转发到 `subagent` 提示词。** 未采用，因为包括工具参数、文件和 shell 在内的每个转发通道都是模型编写的数据流；阻止一个通道会增加状态，但无法封闭这一类问题。

## 后果

配置的第三方结果文本具有可见分隔，常见结构化提示注入形式得到中和，同时普通类代码文本保持不变。纯文本沿用现有溢出与检索行为，混合文本则具有显式部署上限。组合首次包含该策略时，稳定区段会一次性改变系统提示词字节并建立可复用的新 KV-cache 前缀。Web 和根 `run_code` 结果字节包含围栏，Web 结果使用该围栏而非逐结果提示前缀。

该保证刻意限定通道：shell、文件、转发的工具参数以及进程外子项内容需要由各自路径提供防护。固定 Unicode 表和结构识别器一旦变化，都必须通过完整码位、保真性、对抗大小、释放及真实组合测试。
