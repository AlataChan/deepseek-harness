# Agent Note：分阶段上游升级走完第 4 跳、客户端归类与打包链路

Status: implemented

[English](2026-10-08-upstream-hops-three-four-and-packaging.md) | 中文

## 问题

分阶段上游升级的第 1、2 跳带着一个维修检查点落地：intake gate 变得诚实，迁移链在真实数据上得到证明。还剩两跳（`dsh-v0.1.7-alpha.1` 连同 v3 到 v4 的会话格式，然后是引擎与客户端追赶的 `dsh-v0.2.1-alpha.1`）；客户端层仍把 fork 编辑留在上游文件里作为 B 类债；打包链路自 preset 拆分后从未运行，因此没有任何 DMG 验证过合并后的树。

## 决策

两跳都以整树合并落地，按 intake registry 的规则解冲突：class-C 桌面路径保持删除，已登记补丁在上游基线上调和，每一处取上游侧的取舍都有记录。第 3 跳给冻结的 released-v3 词表补上九个 fork 会话事件（先在 scratch 分支上证明，补丁随带通过的测试再入合并），把 `admitSelect` 钩子移植进拆分后的 `agent-preset-registry`，使 ask-data 的选择门不会再静默失效，并让调用点适配上游更名的事件与重塑的输入。第 4 跳贯穿 never-merge 政策对八个客户端包的分析剥离，恢复被合并丢掉的桌面 companion 清单项与构建入口，并在 Loader 开始拒绝 name 与目标行不一致的 patch 行之后重录语料。

客户端层随后应用计划自身的分类法：无法在不编辑上游文件的情况下表达的补丁不是 B，而是带登记理由的 A。死掉的 fork 样式与文案回退到上游 pin，四个已等于 pin 的行删除，每个剩余编辑都登记了能让它可迁移的确切框架缝——renderSlot 绑定声明它的条目，factory 只有一个定义，而 fork 的位置（hero 行、header 前底板、headline、composer 接管）位于上游 JSX 内部。

打包环节产出了合并树的第一个 DMG，并抓到代码审查抓不到的问题：构建仍在复制 preset 拆分已删除的 preset 目录，其 bundle 门也仍断言该目录。该步骤被移除，门改为要求组合型 preset 提供方存在于 harness 闭包内，打包后的 companion 也在复制的旧 profile 上完成验证。

## 验证

两跳的真实数据迁移：152 个日志中的 152 个完成迁移、打开并发布当前代次，原件全程逐字节不变，每个迁移前备份与源逐字节一致。录制的会话语料在 hop-4 写入器上通过，包括 fork 的九个事件。文档门全量通过，配对语料采用上游的分段记录格式。单元套件通过，仅剩的负载型超时全部在隔离下通过。`verify-desktop-bundle` 报告 80 项检查通过并产出 `dist/octopus_DSH.dmg`；对复制旧 profile 的打包握手完成、保持存活并复用两个数据根。遥测 exporter 有断言保证：反馈之前与 `DISABLED` 之下均静默。

## 备选方案

**把客户端 chrome 迁移进 overlay 包。** 被框架自身的绑定规则否决（已在源码中核实）：fork 的位置没有可达的槽位，附近空置的官方单元格只会在存在当前会话时渲染，会丢失 fork UX 依赖的冷启动首页。

**让 B 行停留在愿望状态。** 否决：registry 的分类法存在的意义正是记录什么无法迁移及其原因，而未登记的愿望正是升级要退掉的债。

**在构建中保留独立 preset 目录。** 否决：preset 拆分以组合行取代了文件扫描式 preset；那次复制写入的是一个无人读取的目录。

**用源码重建打包证据而非真实构建。** 否决：死掉的 preset 路径对所有检查都不可见，只有真实 DMG 构建才暴露——这正是把构建当作门的论据。

## 后果

相对上游的每一处 fork 差异，要么是已登记补丁、要么是 overlay、要么是记录在案的组合决策；intake gate 在每一跳强制这一点。打包应用在真实构建上得到端到端验证，真实数据的迁移证据延伸到 v4 格式。owner 剩余的决策是 hop 4 的发布签核，以及迁移为未来上游对话记录下来的客户端缝提案；日期化计划与交接文档承载完整执行记录。
