# Agent Note：拒绝其他 Host 运行时发布的客户端模块

状态：已实现

[English](2026-10-18-runtime-release-reload.md) | 中文

## 问题

缓存的 Client 或重装后重新连接的页面，可能收到不同源码提交的模块，即使壳与 companion 的运行时版本相同。

## 考虑过的替代方案

**仅使用现有 Tauri 版本检查。** 该检查保护已安装的壳与 companion 组合，但无法区分版本号相同、提交不同的旧 Client 包。

**热应用不匹配的图。** 在活动页面下替换共享代码可能混用不兼容的模块状态；要求重新加载可保留当前页面。

## 决策

图携带 Host 运行时发布身份，与插件修订和 Tauri 外壳版本分开。共享桌面构建生成器读取 CLI 运行时版本和完整源码提交。完整 Git 构建通过 `DSH_CLIENT_RELEASE_VERSION` 与 `DSH_CLIENT_RELEASE_COMMIT` 提供身份；现有短 `DSH_CLIENT_COMMIT_HASH` 仍作为显示元数据。Node 和浏览器产物嵌入发布字段，桌面产物元数据读取完整构建记录，并拒绝源码提交变化或产物改动。内部构建保留构建与打包时的源码修改标记；公开构建要求两次检查均为干净状态。

Tauri 引导保留安装清单与伴随进程的运行时版本检查，并在缓存或加载工厂之前比较打包 WebView 内嵌的运行时版本、完整提交与图的身份。本地缓存 URL 改写保留图发布身份。桌面关闭 Client HMR，没有运行中的图更新通道；更新运行时需要重启应用。在启用了 Client HMR 的 Web 组合中，页面在解析或应用替换图之前先读取发布身份。其他发布暂停插件更新并提示重新加载；关闭提示不会接纳该发布。现有页面及其状态继续运行。

没有发布身份的旧图可与同样缺少身份的图协调。身份缺失与存在之间的任意方向切换都需要重新加载。源码和局部构建可缺少提交号；打包要求完整的规范身份。同一发布内的图修订仍可正常更新。

## 影响

发布不一致时，无法在运行中的页面下热替换共享代码。用户可推迟重新加载并保留当前页面。推迟不迁移会话、不删除设置，也不更新应用文件。此流程不依赖账号服务、更新服务器或强制升级策略。
