# Agent Note：直接调用 DeepSeek Search 与 Fetch API

状态：已实现

[English](2026-10-15-deepseek-search-fetch-api.md) | 中文

## 问题

基于 Messages 的搜索需要额外模型生成；直接检索则需要独立的端点、凭据与问题转发控制。

## 考虑过的替代方案

**默认替换 Messages 搜索。** 保留现有默认值，避免未经同意改变网络行为；直接搜索和抓取仍需主动启用。

**包含账号路由。** 账号集成不在本次选择性升级范围内；拒绝该路由可保持 API Key 路径独立。

## 决策

[web-deepseek-api 插件](../../../../packages/web/web-deepseek-api/README.zh.md)注册直接调用的 Search 和 Fetch 提供方。Messages 搜索保持独立，与本地 HTTP 抓取一同作为默认值。设置开关保存后同时选择两个直接调用提供方；每次操作读取当前选择。

直接检索需要 API Key。账号路由请求在发送前被拒绝，包不导入或解析账号凭据。每次操作同时快照配置的端点和凭据引用。携带鉴权的 API 请求拒绝重定向。

发送触发搜索的用户问题需要独立选择，默认关闭。启用后，最近的用户提示会规范化空白，并限制为 128 个 Unicode 字符。直接检索产生正常的工具调用与结果事件，不伪造辅助模型事件。

API 与 Messages 传输保持独立。共享凭据和取消逻辑会耦合两者发布；局部重复标记说明重复的辅助函数。

## 影响

直接 Search 不产生辅助 Messages 生成，但检索来源仍占用主模型上下文。直接 Fetch 将目标检索策略委托给 DeepSeek；成功的 HTTP 200 描述服务响应，而非独立观测的目标响应。本地 HTTP 抓取保留自己的网络检查。

保留的 Messages 路径关闭思考，并记录实际发送的请求正文。[持久化确认](../../../../docs/persistence-changes/2026-10-13-deepseek-search-thinking.zh.md)说明新增的可选日志字段。

## 验证

提供方控制覆盖凭据轮换、明确拒绝账号路由、默认不转发问题、主动启用转发、畸形响应、取消、代理出口和拒绝重定向。设置控制覆盖暂存、保存失败、提供方切换和转发同意。Fetch 会话夹具和网页搜索浏览器场景负责记录产品输出。
